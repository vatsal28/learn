Two things a day, from the workbench.

July 20, 2026 · 3 min read

Two lessons today about making automated systems easier to trust: model their states precisely, and give each agent tool one narrow job.

System Design

Model the State You Actually Have

Explicit states prevent a system from turning distinct conditions into one vague and misleading status.

What it is

A status field is useful only when its values match reality. If a workflow treats drafted, approved, and published as the same condition, downstream reports will confidently say the wrong thing. An explicit state machine names each stage and defines the transitions between them.

Yesterday’s example

Imagine a document pipeline with four states: collected, drafted, approved, and published. A morning summary can then report a waiting draft without mistaking the absence of publication for a failed run.

Why it matters

The concept arose because several healthy workflows were described poorly when distinct operational states collapsed into broad labels.

Takeaway Model meaningful states first; write human-facing status text from those states second.

Read the 2-minute version

The patternFinite-state machineA finite-state machine gives each meaningful condition a named state and permits only deliberate transitions between them.

The important design choice is not adding more labels at random. Each state should answer a question that changes system behavior: may the item be edited, does it need approval, can it be distributed, or should it be retried? Transitions should also carry evidence. Moving from drafted to approved might require a recorded decision; moving from approved to published might require a successful delivery result. This makes impossible combinations easier to reject, such as an item being both unpublished and reported as delivered. It also improves observability because dashboards can show where work is waiting instead of reducing every non-success to failure. When external data arrives late, model that separately from unavailable access. Precise states turn status reporting from guesswork into a deterministic projection of the workflow.

Agents & AI

Give Every Agent Tool One Narrow Job

Narrowly scoped tools help agents fail safely when a request does not match the tool's intended purpose.

What it is

Agents are more reliable when tools encode a narrow purpose instead of exposing a broad action with many unrelated modes. A purpose-specific tool can validate the exact evidence it needs and reject requests that belong to a different workflow.

Yesterday’s example

Suppose an assistant has separate tools for filing reviewed alerts and archiving completed reports. If it sends an alert to the report tool, the mismatched proof requirements stop the action before anything moves.

Why it matters

The pattern surfaced when a safe guard blocked an action because the agent selected a tool built for a different operational context.

Takeaway Treat tool selection as part of authorization, not merely a routing convenience.

Read the 2-minute version

The patternPrinciple of least privilegeA tool should expose only the permissions and inputs required for one well-defined operation.

Least privilege applies to agent interfaces as much as user accounts. A generic file-item tool may look convenient, but it forces the model to remember every policy branch correctly. Smaller tools move those policies into code. Their names, schemas, and preconditions become part of the safety boundary. Good scoped tools also carry provenance: the filing operation can accept only items previously reviewed in the current run, while the archival operation can require proof that a separate process completed. A mismatch then fails closed instead of being interpreted creatively. This does not eliminate planning errors; it limits their blast radius and makes them diagnosable. Logs can distinguish a bad tool choice from an authentication failure or an execution bug. For high-impact actions, the best agent tool is often intentionally boring: few parameters, explicit evidence, a small target set, and no fallback that silently broadens authority.
